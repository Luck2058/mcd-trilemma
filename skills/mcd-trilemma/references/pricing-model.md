# 核价模型与临界时薪推导

## 一、到手价

对第 c 条履约路线：

```
payable(c) = items_total(c) + delivery_fee(c) + packing_fee(c) − deduction(c, coupon*)
```

其中 `coupon* = argmin payable(c, coupon)`，即在本路线可用券池里枚举，
取让到手价最低的那张。三个渠道的 `items_total` 可能不同，因为：

1. **门店不同** → 同款餐品在不同门店可能不同价；
2. **菜单不同** → 外送菜单通常小于门店菜单，某些品在到店有、外送没有；
3. **套餐可替换项不同** → 外送套餐的可替换范围常比到店窄。

`delivery_fee` 只在外送路线非零，且有免配送门槛（本模型取 ¥39，未达则收 ¥9）。
**这是三路差价里最容易被忽略的一项**——一份 ¥36.5 的单子，差 ¥2.5 够不到门槛，就要多付 ¥9。

### 券的抵扣口径（三个易错点）

| 券类型 | 正确做法 | 常见错误 |
|---|---|---|
| 满减券 | 扣商品金额，门槛按 `items_total` 判断 | 把门槛按「券后金额」判断，导致本该可用的券被跳过 |
| 折扣券 | 扣商品金额，注意封顶 | 忘记封顶，大额订单算出负数 |
| 免配送券 | **只把 `delivery_fee` 置零** | 既免配送费又扣商品金额，到手价凭空少 ¥9 |

免配送券那条错误最隐蔽：它让结果看起来更划算，用户不会质疑，但决策就错了。
`selftest.py` 里有专项断言锁死这个口径。

## 二、时间模型

这里必须区分两个容易混的概念：

| 概念 | 定义 | 是否计入成本 |
|---|---|---|
| `active_minutes` 主动时间 | 你必须亲自花掉的时间 | **计入** |
| `total_minutes` 总时长 | 从下单到吃上 | 不计入，仅作参考 |

```python
delivery.active_minutes   = 0                          # 你在家/在工位等，时间是别人的
delivery.total_minutes    = eta                        # 30+ 分钟，但不占用你
pickup.active_minutes     = walk_minutes * 2 + queue   # 往返 + 排队，全是你自己的时间
drivethru.active_minutes  = drive_minutes * 2 + queue
```

**为什么外送主动时间是 0？** 因为外送的 30 分钟等待可以并行做别的事——写代码、开会、追剧。
到店的 16 分钟往返不能并行，它是一段被独占的时间。

这不是「外送一定更好」的偏见：如果用户就是想出门走走、或者久坐需要活动，
那 16 分钟的「成本」其实是负的。这个反例值得在对话里主动提——

> 如果你本来就想下楼透口气，这趟的「成本」得按负的算，那我这套账就不适用了。

## 三、综合成本

```
cost(c, w) = payable(c) + active_minutes(c) / 60 × w
```

`w` 是用户时薪（元/小时）。推荐路线 = `argmin cost(c, w)`。

这里的 `w` 是**时间的机会成本**，不是「你一小时挣多少钱」的字面意思。
对没有工资的学生，它更接近「这一小时本来能用来干什么」的估价。
所以不要死套默认值 ¥45，要跟用户确认——这个参数直接决定结论。

## 四、临界时薪

设 A 便宜但慢、B 贵但快：

```
payable(A) < payable(B)  且  active(A) > active(B)
```

令 `cost(A, w) = cost(B, w)`：

```
payable(A) + T_A/60 × w = payable(B) + T_B/60 × w
w* = (payable(B) − payable(A)) × 60 / (T_A − T_B)
```

`w*` 就是临界时薪：

- `w < w*` → A 的综合成本更低 → **走 A（省钱）**
- `w > w*` → B 的综合成本更低 → **用 B（省时间）**
- `w = w*` → 两条路完全等价，随便选

**直觉**：`w*` 是「你愿意为省这一笔钱付出的最高时薪」。
它把一个模糊的纠结变成了一个可以跟自己的工资对比的数字——这就是本 Skill 的全部价值。

### 推导的边界条件

| 情形 | 处理 |
|---|---|
| `T_A = T_B` | 无临界时薪，纯比价格 |
| `payable(A) ≥ payable(B)` | A 又贵又慢，不是「便宜但慢」，不进讨论 |
| A 不可用（无门店/未达起送） | 跳过，但要在输出里说明原因 |
| 只有一条路可用 | 不提临界时薪，直接给这条路的到手价并说明为什么只剩它 |

## 五、帕累托前沿

在 `(payable, active_minutes)` 双目标下求不可支配解集：

```
q 被支配 ⟺ ∃ o ≠ q : payable(o) ≤ payable(q) 且 T(o) ≤ T(q)，且至少一项严格更小
```

前沿上的路线意味着：想要更便宜，就必须花更多时间；想要更省时间，就必须多花钱。
没有第三条路能同时满足两者。落在前沿外的路线，无论你的时薪是多少都不会是最优解——
**这是可以理直气壮从推荐里删掉的**。

## 六、凑单的边际成本

外送被收配送费时，加购一件商品跨过门槛的**真实代价**不是商品原价：

```
marginal = payable(加购后) − payable(加购前)
```

例：餐品 ¥36.5，配送费 ¥9，门槛 ¥39，用券满 15 减 3。

| 情形 | 商品金额 | 配送费 | 券 | 到手价 |
|---|---:|---:|---|---:|
| 不凑 | 36.5 | 9 | −3 | 42.5 |
| 加香芋派 ¥8 | 44.5 | 0 | −3 | 41.5 |

加购后到手价反而更低——`marginal = −1.0`，等于白得一个派还省 ¥1。
即使边际成本为正，只要它低于商品原价，就是「打折买」而不是「被迫凑单」。
**不要把这句说成「建议你多买一个」**，要说清「多付多少换到什么」，让用户自己决定。
